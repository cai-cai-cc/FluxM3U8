# FluxM3U8 · 安卓版

一个 M3U8 / HLS 视频下载器，功能对标 `roomanl/famd`，但**架构和界面全部重写**。

最核心的改进：**下载引擎以前台服务常驻，锁屏、切后台、划掉应用都不会中断，也不会掉速。**

---

## 一、为什么 famd 挂后台就没速度，而本项目不会

| 对比项 | famd（Flutter + aria2） | FluxM3U8（Kotlin + Compose） |
|---|---|---|
| 下载执行者 | Flutter 界面进程拉起 aria2 子进程 | 前台服务（Foreground Service）里的 Kotlin 协程 |
| 界面与下载 | 强耦合：界面进程负责拉起、轮询 RPC、写进度 | 完全解耦：界面只观察 StateFlow，退出不影响下载 |
| 切后台 / 锁屏 | 进程被系统降频或冻结，子进程随之停摆，速度掉到 0 | 前台服务 + 常驻通知，系统优先保活 |
| 熄屏后 | CPU 休眠，连接断开 | 持有 **CPU 唤醒锁 + WiFi 锁**，持续满速 |
| 划掉应用 | 一并被杀 | `stopWithTask="false"`，服务存活 |
| 保活配置 | 无 | 引导加入电池优化白名单、通知权限、开机自启恢复 |
| 断点续传 | 依赖 aria2 会话文件，异常退出易丢 | 每片先写 `.part` 再改名，重启后自动续跑 |
| 外部依赖 | 需自带 aria2 / ffmpeg 二进制（体积大、架构适配麻烦） | 内置 ffmpeg-kit（仅用于 MP4 转码）；下载 / 解密 / 合并仍是纯 Kotlin |

一句话概括：**famd 是"界面带着下载跑"，FluxM3U8 是"下载自己跑，界面只是个遥控器"。**

## 二、界面（Jetpack Compose · Material 3）

刻意不沿用原项目的 Material 列表风格，按当下安卓主流审美重做：

- **主界面**：顶栏 + 统计卡（实时总速度 + 速度曲线）+ 筛选 Chip + 卡片流
- **任务卡片**：渐变进度条、实时速度、剩余时间、分片进度、清晰度 / 加密 / 直播标签
- **新建任务**：粘贴链接自动解析，展示时长、分片数、加密状态；多清晰度可选；高级选项里填 Referer / Cookie 破防盗链
- **设置**：存储 / 下载 / 后台与省电 / 输出 / 网络 / 外观 分组，改完即时生效
- 深色为主，支持 **Material You 动态取色**（Android 12+）与浅色主题
- 支持从浏览器或其他 App **分享 m3u8 链接**直接唤起新建窗口；
  分享文本里带标题（如「视频标题\n链接」）会自动填入「名称」，不带则按链接自动猜名

## 三、功能

- 多清晰度（Master Playlist）自动识别，可手动选择
- AES-128 加密流自动解密，兼容二进制与 hex 文本两种密钥格式
- fMP4（`EXT-X-MAP`）与 MPEG-TS 双形态
- 直播流持续拉取（无 `EXT-X-ENDLIST` 时自动刷新追加分片）
- 三层并发（任务 / 分片 / 分块）均可调，支持自动并发、全局限速、自定义 Referer / UA / Cookie、HTTP 代理
- **失败重试可配**：重试次数 + 重试间隔（线性退避，间隔 × 第几次失败）
- 分片级断点续传 + 重启 / 开机自动恢复未完成任务
- 临时分片自动清理（详见下方「临时文件清理」）
- 下载完成通知、失败通知，通知栏可直接全部暂停 / 继续 / 停止
- 保存到内部目录（免权限）或任意 SAF 目录（公共下载目录、SD 卡）
- **自定义下载目录**：内部子目录可任意分级，也能一键定位到系统「下载」「影片」等公共目录
- **边下边播**：下载中的点播任务可直接开播，已下好的分片读本地，没下到的自动回源；
  **下载完成后点同一个按钮就是直接打开本地成品文件**，开播即"打开一个文件"
- **单文件产物**：不转 MP4 时把分片合并成**一个** `.ts` 文件，下载目录里只有这一个文件，
  既不逐片复制、也不再额外写 `.m3u8` 索引（详见下方「输出格式」）
- **防相册识别**：设置 → 输出 打开开关后，已完成任务可一键「转换 / 还原」文件名伪装后缀
  （`xxx.mp4` → `xxx.mp4.flux`），系统相册不再收录下载的视频；删除伪装文件时弹窗会特别说明，
  播放器照常支持播放（详见下方「防相册识别」）

### 下载目录

保存位置用一串字符串表示（`Settings.saveDir`）：

| 取值 | 含义 |
|---|---|
| `internal` | 内部默认目录 `Android/data/<pkg>/files/Movies` |
| `internal:A/B` | 内部自定义子目录，如 `internal:剧集/第一季` |
| `content://…` | 用户通过系统文件选择器授权的 SAF 目录 |

**默认目录**：首次安装为内部 `Movies`，零权限、任何安卓版本都能写。

**异常处理**：

| 情况 | 处理 |
|---|---|
| SAF 授权被系统回收 | 设置页显示「授权已失效，请重新选择」；下载前自动**回退内部目录**，不让下载白跑 |
| 目录不可写 / 不存在 | 同上回退；回退失败才报错 |
| 子目录填了 `../../etc` 之类 | `safeRelativePath()` 过滤 `..` 与非法字符，结果一定在私有目录内 |
| 合并写文件失败 | 删除半成品，避免留下打不开的"成品" |
| 同名文件已存在 | **提示并阻止下载**（不覆盖、也不自动改名）；新建弹窗直接拦在开始前，任务列表里长按可改名后重试 |

校验分两层：设置页做**带探针文件**的完整检查（建一个再删，避免 `canWrite()` 说谎），
下载开始前再兜一次——因为授权可能在 App 运行期间失效。

### 输出格式

不勾「转换为 MP4」时：**下载目录里只落一个 `<任务名>.ts`**（见 `HlsOutput`）——
分片按顺序拼成一个文件，一次建文件、顺序写一遍，任何失败都会删掉半成品。

| 情况 | 产物 | 建文件次数 |
|---|---|---|
| 默认（不转 MP4） | `<名>.ts` | 1 |
| 勾选「转换为 MP4」 | `<名>.mp4`，封装全部失败则回退成 `<名>.ts` | 1 |

**为什么不再逐片复制**：一个千片任务意味着上千次建文件 + 上千次全量拷贝，
在 SAF 目录上每次 `createFile` 还是一次跨进程调用，慢到像卡死；
播放器开播也要逐个打开上千个文件；下载目录里还会多出一堆不认识来源的分片。

**为什么不写进 `.m3u8`**：`.m3u8` 是**纯文本索引**（每行一条分目地址），视频数据物理上装不进去。
· 把媒体追加在播放列表后面 → media3 1.3.1 的 `HlsPlaylistParser` 只在读到**文件末尾（EOF）**
才结束解析（`#EXT-X-ENDLIST` 只置标志位，见其 `parseMediaPlaylist`），追加的二进制会被当文本
逐行解析出成百上千条假分目，播放必然失败；
· 用 `data:` URI 把媒体 base64 塞进播放列表 → 体积 +33%，且播放器要把整条 URI 读进内存，
几百 MB 的文件直接 OOM。
`.ts`（MPEG-TS）本身就是「整段视频装在一个文件里」的容器，还免去一次二次转换。

**已完成任务的播放**：`PlaybackManager.localFileUri()` 直接给出本地产物地址，
播放页**不起本地代理、不查分片、不碰网络**，点开就是打开一个文件。

勾了「转换为 MP4」则走 `FfmpegConverter`：合并 TS → 交给 **ffmpeg** 依次尝试
`-c copy` 流拷贝 → 硬件重编码 → 软件重编码，全部失败时把已合并好的 TS 直接落盘（不重复拼一遍分片）。
两条路径的结局一定是「已完成」或「失败」——不会停在「合并中」，也不会卡在 99%。

**转 MP4 的 ffmpeg 依赖**：原版 `com.arthenica:ffmpeg-kit-min` 已从 Maven Central 下架，
改用社区重建版 `io.github.maitrungduc1410:ffmpeg-kit-min:7.1.5`（API 包名不变），
只参与转码阶段，不影响下载与边下边播。

### 防相册识别（后缀伪装）

设置 → 输出 →「防相册识别」开关（默认关）。开启后：

- 已完成任务的操作区出现「转换 / 还原」图标按钮：转换 = 在文件名后追加伪装后缀 `.flux`
  （`xxx.mp4` → `xxx.mp4.flux`），还原 = 去掉后缀恢复原文件名，随时双向切换；
- 伪装后缀不在系统媒体 MIME 映射表里，下载的视频不会被扫进系统相册；
- 删除**处于伪装状态**的任务时，确认弹窗会额外提示「文件后缀已被伪装、相册不会收录，
  如需恢复为普通视频请先点还原再决定是否删除」；
- 播放器对伪装文件照常支持：按文件名里保留的原始扩展名显式指定 MIME
  （`.mp4.flux` → video/mp4，`.ts.flux` → video/mp2t），本地播放与进度记忆不受影响。

> 伪装不重新编码、不动视频内容，只是改文件名，瞬时完成
> （内部目录直接 rename；SAF 目录优先 `renameDocument`，个别提供方不支持时回退复制+删除）。

### 边下边播（Download while playing）

原理：在 `127.0.0.1` 起一个**本地回环 HTTP 服务**，把任务的分片目录伪装成标准 HLS 源，
播放器访问 `http://127.0.0.1:<随机端口>/<token>/<任务ID>/index.m3u8`：

| 请求的分片 | 处理 |
|---|---|
| 已下载完成 | 直接读本地 `.ts` 分片，**不再消耗带宽** |
| 尚未下载 | 服务端**按需回源**拉取（含 AES-128 解密）后转发给播放器，并缓存 |
| 加密流 | 本地分片已是解密后的，本地播放列表里去掉 `EXT-X-KEY`，播放器无感知 |

**支持场景 / 触发条件**（见 `PlaybackManager.isPlayable`）：

- 点播（VOD）任务，状态为 下载中 / 暂停 / 失败但仍有分片，且**已缓冲 ≥ 2 个分片或 ≥ 6 MB**
- 已完成的任务：**直接播放本地成品文件**（不走本地代理、不回源，开播最快）
- **不支持**：直播流（播放列表不断增长、`media sequence` 滑动，本地分片按序号命名无法对齐）、已取消任务（临时分片已删）

**协同与异常：**

| 情况 | 行为 |
|---|---|
| 播放中拖动到未下载位置 | 本地服务按需回源，播放器正常缓冲，不影响下载任务本身 |
| 播放中任务被取消 / 移除 | 任务从列表消失，播放页自动关闭 |
| 回源失败（源站限流、断网） | 该分片返回 502，播放器报错，覆盖层提供「重试」 |
| 播放页关闭 | 注销会话、停掉服务、删除按需回源缓存 |

**播放形态**：进入播放页即**横屏 + 沉浸式全屏**（隐藏状态栏 / 导航栏，退出自动还原）。
页面内**不提供「退出全屏」按钮**——手机上看视频基本没人想切回竖屏，留着只占地方还容易误触。
倍速支持 0.5x / 0.75x / 1.0x / 1.25x / 1.5x / 2.0x / 3.0x（上限 3x：再高会音画不同步、掉帧）。

**安全**：只绑定 `127.0.0.1`，路径带一次性随机 token，分片索引只接受纯数字（无路径拼接），
因此外部应用与局域网均无法访问。

> 依赖 `androidx.media3`（ExoPlayer）做播放，manifest 里 `usesCleartextTraffic=true`
> 保证回环明文 HTTP 可用。

## 四、速度调优（能不能跑满带宽）

三层并发，全部可调，实际并发数 = **三者相乘**：

| 层级 | 设置项 | 默认 | 说明 |
|---|---|---|---|
| ① 任务并发 | 每任务并发连接数 | 16 | 同时下载多少个**分片**，影响最大 |
| ② 任务数 | 同时下载任务数 | 2 | 几个视频一起下 |
| ③ 分块并发 | 单分片分块线程数 | 4 | 把一个**大分片**切成几段并行拉取 |

> 「同时下载任务数」超出的任务会自动**排队**，前面的下完再依次补位；
> 「全部开始」也受同一个上限约束，不会一次性全开。

**为什么需要第 ③ 层**：M3U8 常见两种形态——

- 分片多而小（几百片 × 1MB）：靠 ① 就能跑满，③ 不触发（小于 2MB 不分块）
- **分片少而大**（10 片 × 50MB）：① 最多只能开 10 条连接，单条连接往往跑不满带宽，
  必须靠 ③ 把每个分片再切 4 段，才能凑够 40 条连接压满带宽

分块依赖服务器支持 HTTP Range；不支持时自动降级为单连接，不影响下载。

**失败重试**：分片下载失败后等待「重试间隔 × 第几次失败」再试（间隔 2 秒即 2s / 4s / 6s…）。
源站在限流时把间隔调大；设为 0 表示立即重试，仅建议用于确认是偶发抖动的场景。

**自动并发**：打开后从 4 条起步，每 2.5 秒测一次速度，涨了就加、连续两次不涨就收，
自动找到"再加也没用"的拐点，避免盲目开满被源站限流。

> ⚠️ 并发不是越大越好。开太大可能触发源站限流甚至临时封 IP，
> 一般 **16 × 2** 已能跑满大多数家用宽带。

### 已修复的性能瓶颈

OkHttp 默认 `maxRequestsPerHost = 5`——**同一域名最多 5 条并发请求**。
若不覆盖这个默认值，界面上设 64 并发实际也只有 5 条生效，速度被死死锁住。
本项目按 `并发 × 任务数 × 分块数 + 16` 动态设置，上限 256。

## 五、临时文件清理

下载过程会在 `cacheDir/seg/<任务ID>/` 产生未合并的 `.ts` 分片与 `.part` 半成品。

**正常流程自动清理：**

| 时机 | 行为 |
|---|---|
| 下载完成 | 保存成功后删除分片与合并 / 转换的中间产物（开启「保留分片」除外） |
| 取消任务 | 立即删除 |
| 移除任务 | 立即删除分片；**本地成品文件默认保留**，删除前会弹窗问「仅移除任务 / 同时删除文件」 |
| 清空已完成 | 一并删除 |
| 重试任务 | 先清空再重下 |
| 每次启动 | 异步扫描清理残留 |

**兜底清理（新增 `TempCleaner`）：**

进程被强杀或应用崩溃时，清理代码根本没机会执行，分片就成了没人认领的孤儿。
启动时延迟 2 秒自动扫一遍，三条规则：

- 目录名不在数据库中 → 孤儿，删
- 超过 **7 天**没改动 → 多半已废弃，删
- 所有 `.part` 文件 → 半截半成品，一定没用，删

**安全边界（不会误删）：**正在下载、暂停待续传的任务，其 `.ts` 分片一律保留，
只清 `.part`——否则断点续传会失效。设置页「临时文件」一栏可查看占用并一键清理残留。

## 八、后台保活的四个必要条件（都在代码里做了）

1. **前台服务 + 常驻通知** —— `DownloadService` 调 `startForeground`，manifest 声明 `foregroundServiceType="dataSync"`
2. **CPU 唤醒锁** —— `PowerManager.PARTIAL_WAKE_LOCK`，保证熄屏后 CPU 继续工作
3. **WiFi 锁** —— 防止系统为省电在熄屏后断开 WiFi
4. **电池优化白名单** —— 设置页一键跳转，指引用户放行

> 国内 ROM（小米 / 华为 / OPPO / vivo 等）还需要额外在「手机管家 → 应用管理」里
> 把本应用设为**自启动 + 后台运行无限制**，否则系统仍可能冻结后台。
> 设置页里也放了这段提示。

## 八点五、安全与隐私

| 项 | 现状 |
|---|---|
| TLS | 默认**严格校验证书**。「设置 → 网络 → 跳过 HTTPS 证书校验」关闭；只有确认是源站证书链问题时才临时打开 |
| Cookie | 任务的 Cookie 用 **AndroidKeyStore 的 AES-256-GCM 加密**后落盘；KeyStore 不可用时降级为明文（不会让下载挂掉） |
| 备份 | `allowBackup="false"` 加上 `data_extraction_rules.xml` 排除全部数据域。**Android 12+ 的 `allowBackup` 只管云备份**，换机迁移是另一条通道，必须靠前者一起堵；两条通道现在都导不出任务库与凭证 |
| 明文流量 | `network_security_config.xml` 显式放行 `127.0.0.1`（边下边播的本地代理）；远程 http 源站仍允许，源站全 https 时可把 `base-config` 改成 `false` 全网收紧 |
| 本地播放服务 | 只绑定回环地址、路径带一次性随机 token、分片索引只接受纯数字 |
| 数据库 | 全部参数化查询；升级只补列、绝不删表 |

## 九、已知限制

- 仅支持 `http` / `https` 的 M3U8 地址，不支持 mpd / flv 等其它协议
- 默认输出**一个单文件 `.ts`**（下载目录里就这一个文件，可直接播放）——`.m3u8` 是纯文本索引，
  装不下视频，具体原因见「输出格式」。
  **转 MP4 走 ffmpeg**（内置 ffmpeg-kit）：先 `-c copy` 流拷贝（不重编码、速度快），
  源文件与 MP4 封装不兼容时自动降级为硬件 / 软件重编码，全部失败则回退为 `.ts`
- 暂不支持独立音轨 / 字幕轨
- 本工程未经真机编译验证（开发环境无 Android SDK），若 Gradle 同步报错，
  优先看 [BUILD_GUIDE.md 第三节 常见问题排查](BUILD_GUIDE.md#第三节--常见问题排查)
